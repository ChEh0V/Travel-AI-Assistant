# Данные и хранение

## Нужна ли база данных

Для текущего фронтенда серверная БД не нужна. Данные сохраняются в `localStorage` конкретного браузера и origin (протокол, адрес, порт). При смене порта сохранения могут выглядеть отсутствующими. Между устройствами они не синхронизируются; очистка данных сайта удаляет их.

Для первого RAG можно начать с версионируемых файлов корпуса и индекса в памяти. PostgreSQL или другое постоянное хранилище выбирается позже, если появятся аккаунты, синхронизация или требования к объёму и обновлению. Охват Европы прежде всего требует отбора и поддержки источников, а не обязательной большой БД на КТ1.

## Сущности текущей версии

| Сущность | Основные данные | Связь |
|---|---|---|
| Поездка | `id`, `city`, `days`, `pace`, `interests`, `preferences` | Владелец всех локальных данных сценария |
| Переписка | `messages`: роль, текст, дополнительные данные карточек | Принадлежит поездке |
| Маршрут | `plan`: массив дней с местами, `day`: выбранный день | Места берутся из подготовленного каталога |
| Даты | `dates.start`, `dates.end` | Общие для маршрута, погоды и сборов |
| Избранное | `wishlist`: места с городом | Для явной сборки нового плана |
| Сборы | `packing`: отметки, собственные пункты, прогноз | Прогноз связан с городом и датами |
| Бюджет прежнего формата | `budget` | Сохранён для совместимости, отдельного UI нет |

## Ключи и правила

- `travelai-chat-v2` — текущее состояние.
- `travelai-chat-archive-v1` — архив до 12 поездок.
- Новая запись добавляется в начало; обновление сохраняет её индекс. При превышении лимита последние записи не входят в сохраняемый архив.
- При чтении JSON проверяются основные поля; повреждённые данные не считаются полноценной поездкой.
- Ошибка записи отображается статусом «Сохранение недоступно».
- Старые даты сборов переносятся в общие даты, старый `vibe` удаляется; ключи выбора темы больше не используются.

## Удаление и внешние запросы

`withoutRoute` очищает `plan` и выбранный день, сохраняя остальные поля. `removeTrip` удаляет запись по `id` и сохраняет порядок остальных. Для текущей удаляемой поездки создаётся пустое состояние и отменяется запрос погоды, чтобы последующее сохранение не вернуло удалённую запись.

Локальные данные не шифруются приложением. Аккаунтов и разграничения доступа нет; приложение рассчитано на личный браузер. Внешнему погодному сервису передаются координаты города и даты; переписка в LLM сейчас не отправляется.
