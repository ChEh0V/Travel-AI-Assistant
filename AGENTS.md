# Правила репозитория

## Контекст

«Попутчик» — настольный ассистент для поездок по Европе. Основной экран — чат. Сейчас готовится КТ1: статический фронтенд с подготовленными ответами, без BM25 и LLM. Карта документации — [docs/README.md](docs/README.md).

## Порядок работы

1. Прочитать `spec/product` и затрагиваемые документы `spec/tech` и `docs`.
2. При изменении поведения актуализировать требования и сценарии, затем реализацию.
3. Выполнить относящиеся к изменению проверки. Для логики — `node --test`, для UI — сценарии из `spec/product/scenarios.md`. Для документации — проверить ссылки и соответствие коду.
4. Зафиксировать результат и ограничения в `spec/verification.md`, изменение — в `CHANGE_HISTORY.md`.
5. RAG benchmark запускать только при наличии корпуса и runner. Иначе записывать `not_run` с причиной, без выдуманных метрик.

## Контракты и ограничения

- Действующий контракт: `getReply(messages, context)` из `app/planner.js`; изменения согласовывать с `docs/dialogs.md` и `spec/tech/architecture.md`.
- `app/mock.js` — прежняя неподключённая реализация. Подготовленные ответы не выдавать за RAG.
- Для будущего RAG ответ должен опираться на найденные документы; при недостатке данных нужен честный отказ или уточнение.
- Ключ LLM не хранить во фронтенде и не коммитить. Официальные билетные ссылки не считать RAG-цитатами.
- Сохранять единые даты, стабильный порядок поездок и различие удаления плана и всей поездки.
- Тема только фиолетовая; мобильная версия и отдельные страницы бюджета/источников не входят в текущий интерфейс.

## Статус макета

По решению пользователя служебные надписи «демоверсия», «КТ» и статус подключения ИИ не добавляются в продуктовую оболочку. Реальная стадия и ограничения явно описываются в README и спецификациях. Изменение надписей не означает подключения настоящего RAG. При недоступности браузера не объявлять визуальную проверку выполненной.
