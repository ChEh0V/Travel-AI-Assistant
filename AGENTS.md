# Правила репозитория

Перед изменением кода:

1. Прочитай `spec/product` и `spec/tech`.
2. Обнови нужную спецификацию, если меняется поведение.
3. Запусти тесты (`node --test`) и benchmark (`benchmark/`).
4. Обнови `CHANGE_HISTORY.md`.

## Ограничения

- Ответ ассистента строится только на найденных документах корпуса; если ничего не найдено — честно сообщаем и предлагаем переформулировать.
- API-ключ LLM не хранится во фронтенде и не коммитится.
- Интерфейс получает ответ через одну функцию `getReply(messages)` — её контракт не меняем без обновления `spec/tech/architecture.md`.

## Проверка

- Интерфейс: пройти основной сценарий из `spec/product/scenarios.md` (С1).
- Логика ответов: `node --test`.
- RAG: прогнать `benchmark/questions.json`, сохранить результат в `benchmark/results/`.

## Правила текущего этапа
- Продукт — путешествия по Европе. Не сужать общий интерфейс до одного демогорода.
- Работаем над настольным фронтендом КТ1. Ответы и планы заглушки маркируем явно.
- Текущий контракт `getReply` описан в `spec/tech/architecture.md`; `app/mock.js` — прежняя неподключённая реализация.
- Не представлять официальные ссылки в демо как найденные RAG-цитаты.
- При отсутствии корпуса/runner не имитировать успешный benchmark: сохранить честный статус «не запускался» и причину.

## Служебные пометки в интерфейсе
По прямому запросу пользователя надписи «демоверсия», «КТ» и статус подключения ИИ не показываем в продуктовой оболочке. Реальную стадию реализации и ограничения сохраняем в README и спецификациях. Не выдавать это изменение текста за подключение реального RAG.
