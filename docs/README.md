# Документация «Попутчика»

Каталог связывает продуктовые требования, описание реализации и результаты проверки. Состояние: КТ1, настольный фронтенд. Документация будущего RAG обозначена как план; она не подтверждает наличие backend.

## Состояния компонентов

«Реализовано» означает наличие кода, а не прохождение всех ручных проверок. Фактически выполненные проверки перечислены в отдельном отчёте.

| Компонент | Состояние | Реализация |
|---|---|---|
| Чат и редактирование маршрута | Реализовано на подготовленных данных | [app.js](../app/app.js), [planner.js](../app/planner.js) |
| Архив и удаление поездок | Реализовано, локальное хранение | [travel-tools.js](../app/travel-tools.js) |
| Избранное, даты, сборы и подбор города | Реализовано | [companion.js](../app/companion.js), [companion-ui.js](../app/companion-ui.js) |
| Погода | Подключён внешний API; требуется сеть | [companion-ui.js](../app/companion-ui.js) |
| Карты и билетные сайты | Внешние ссылки; нет загрузки цен и сеансов | [travel-tools.js](../app/travel-tools.js) |
| Корпус, BM25 и генерация LLM | Запланировано | [Спецификация](../spec/tech/rag.md) |
| Серверный API и серверная БД | Не реализовано; выбор хранения отложен | [Границы интеграции](dialogs.md) |
| RAG benchmark | Черновые вопросы, запуск невозможен без корпуса и runner | [Статус](../benchmark/results/2026-10-22-status.json) |

## Как поддерживать документацию

Требования живут в `spec/product`, технические решения — в `spec/tech`, порядок работ — в `spec/plan.md`, свидетельства проверки — в `spec/verification.md`. `docs/` помогает найти эти документы и описывает действующие контракты. При изменении поведения обновляются связанные страницы и `CHANGE_HISTORY.md`. Исторические записи не заменяют актуальные требования.
