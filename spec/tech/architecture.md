# Архитектура «Попутчика»

## Фронтенд КТ1
Статический HTML/CSS/JS без npm-зависимостей. Основные файлы:
- index.html — оболочка, страницы и диалоги.
- styles.css, features.css, companion.css, atlantic.css — единственная синяя «Атлантика» тема и оформление.
- app.js — чат, DOM, hash-навигация, архив, удаление и экспорт.
- planner.js — данные городов, маршруты и заглушка getReply.
- companion.js — чистая логика дат, погодных рекомендаций, подбора города и маршрута из избранного.
- companion-ui.js — даты, чек-лист, избранное, запрос Open-Meteo.
- travel-tools.js — внешние ссылки, компания, обновление/удаление архива.
- mock.js — прежняя неподключённая заглушка; budget.js — прежний расчётный модуль без текущего UI.

## Контракт
getReply(messages, context) → Promise<{reply, action, city}>. Это ограниченная демонстрационная логика, не LLM. Action может обновлять город, бесплатные места, темп, прогулки или формировать инстаграмную подборку. Ввод пользователя рендерится textContent.

## Навигация и хранение
#chat, #trips, #route, #packing. В sidebar только первые две страницы. Прокрутка локальна рабочей области, composer остаётся внизу.
Ключи localStorage сохранены для совместимости: travelai-chat-v2 (текущая поездка), travelai-chat-archive-v1 (до 12 записей). Старые ключи выбора тем игнорируются.
Состояние: id, city, days, pace, interests, preferences, plan, day, messages, dates, packing, wishlist, budget (legacy).
Обновление записи — по прежнему индексу; только новая добавляется в начало. Переключение восстанавливает копию, не сортирует список.

## Даты и погода
state.dates — единый источник периода 1–3 дня; прежние packing.start/end мигрируют. Open-Meteo вызывается по кнопке для координат выбранного города и дат в горизонте до 16 дней. Есть таймаут, проверка полноты ответа и отмена при смене поездки. Ответ применяется только к исходным id/city/dates. Базовый чек-лист работает без сети. Даты плана не являются реальными слотами музеев.

## Избранное и ссылки
Места в ответах сопоставляются с каталогом по имени и городу. Явно выбранные места текущего города распределяются по дням без дублей, pinned=true. Географическая оптимизация не выполняется.
Внешние Maps URL кодируются; билетные URL задаются allowlist, не извлекаются из сообщений. Ссылки используют noopener noreferrer. Покупки внутри приложения не выполняются.

## Удаление
withoutRoute возвращает копию с plan=[] и day=0. removeTrip фильтрует выбранный id, сохраняя порядок остальных. Перед изменением состояния пользователь видит описание последствий. При удалении текущей поездки сетевой запрос отменяется и создаётся пустое состояние, чтобы save не восстановил удалённую запись.

## Целевой RAG и проверка
Интерфейс → сервер /api/chat → контекст + BM25 → LLM → ответ по документам с источниками. Ключи только на сервере. Корпус и рабочий сервер ещё не реализованы.
Проверки: node --test, node --check для JS, ручные сценарии spec/product/scenarios.md. Benchmark не запускается без корпуса/runner. В текущей инструментальной сессии визуальная QA браузером недоступна.
