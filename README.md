# Попутчик

**Контекстный ассистент для путешествий по Европе.** Обсудите поездку в чате, сохраните понравившиеся места и соберите маршрут по дням.

## О проекте

Учебный проект НИРС, группа ИУ5-51Б. Пользователь — самостоятельный путешественник, который планирует короткую поездку и собирает информацию из разных путеводителей. Цель «Попутчика» — сохранить пожелания в одном диалоге, помочь выбрать направление и превратить выбранные места в редактируемый план.

В целевой версии ассистент ищет сведения в документах через **BM25**, затем LLM формирует ответ с учётом контекста поездки. Качество поиска и ответов команда проверит на собственном benchmark. Текущая реализация описана ниже отдельно от этого плана.

Навигация: [документация](docs/README.md) · [требования](spec/product/product.md) · [сценарии](spec/product/scenarios.md) · [план работ](spec/plan.md) · [проверки](spec/verification.md).

## Статус проекта

Контрольная точка 1: интерактивный настольный фронтенд. Диалог и маршруты работают на подготовленных данных и правилах. **Корпус путеводителей, поиск BM25 и LLM пока не подключены.** Следующий этап — ответы по найденным документам и собственный benchmark.

Демонстрационные направления: Рим, Париж, Барселона, Прага, Вена и Лиссабон. Это примеры для макета, а не окончательные границы покрытия Европы.

## Быстрый запуск

Нужен Python 3. Из корня репозитория:

```bash
python -m http.server 8000 --directory app
```

Для первого запуска получите репозиторий: `git clone https://github.com/ChEh0V/Travel-AI-Assistant.git`, затем `cd Travel-AI-Assistant`. Остановить сервер можно через Ctrl+C. API-ключи, `.env`, Docker и установка базы данных для КТ1 не нужны.

Откройте **http://localhost:8000/#chat**. Устанавливать npm-пакеты не требуется.

Для прогноза погоды нужен доступ к Open-Meteo. Шрифт Manrope загружается из Google Fonts; при отсутствии сети используется системный шрифт. Маршруты, избранное и сборы хранятся локально в браузере, без аккаунта и серверной БД.

## Основной сценарий

1. Напишите «Составь маршрут по Парижу на 2 дня» или нажмите пример на стартовом экране.
2. Уточните: «Сделай спокойнее», «Больше бесплатного», «Замени музеи на прогулки».
3. Нажмите **«Хочу сюда»** у понравившихся мест. Откройте список, отметьте нужные и нажмите **«Собрать маршрут из выбранного»**. Новый план заменит предыдущий; выбранные места закрепятся.
4. Задайте общие даты поездки кнопкой в шапке или сообщением, например «25.10–27.10». Маршрут, погода и сборы используют один период.
5. В **«Моих поездках»** откройте чат, маршрут или сборы нужной поездки. Порядок карточек не меняется при переключении.

## Возможности макета

- Чат, быстрые уточнения, подбор города по свободному описанию и подборка «Инстаграмные места».
- Качественные предпочтения жилья, еды, транспорта, впечатлений и компании. Вайба, денежных ползунков и обязательной большой формы нет.
- Маршрут на 1–3 дня: переключение дней, закрепление, замена мест и экспорт TXT.
- «Хочу сюда» с явной сборкой маршрута из выбранного, без повторов. Географическая оптимизация пока не выполняется.
- Ссылки на Google Maps, отзывы и последовательность остановок дня; официальные билетные страницы у проверенных объектов. Цены, сеансы и наличие билетов автоматически не загружаются.
- Сборы: базовый чек-лист, собственные пункты, отметки и советы по одежде. Прогноз Open-Meteo доступен только на ближайшие даты в пределах 16 дней; без прогноза конкретные погодные значения не выдумываются.
- До 12 локальных поездок, поиск, сохранение истории, дат, избранного и сборов.
- **Удалить маршрут:** очищается только план; чат, даты, сборы и избранное сохраняются.
- **Удалить поездку:** удаляется вся выбранная поездка после подтверждения, остальные остаются на месте.

Единственная цветовая тема — синяя «Атлантика»; символ проекта — компас. Основная навигация содержит «Ассистент» и «Мои поездки»; маршрут и сборы открываются в контексте конкретной поездки.

## Проверка

### Команды

| Задача | Команда из корня репозитория |
|---|---|
| Запустить интерфейс | `python -m http.server 8000 --directory app` |
| Проверить логику | `node --test` |
| Проверить синтаксис основного UI | `node --check app/app.js` |
| Проверить синтаксис дополнительных функций | `node --check app/companion-ui.js` |
| Проверить оформление diff | `git diff --check` |

Отдельного сборщика, линтера и команды запуска RAG пока нет. Описание конфигурации и решения проблем — в [руководстве запуска](docs/configuration.md).

Для тестов нужен Node.js 18+:

```bash
node --test
node --check app/app.js
node --check app/companion-ui.js
```

Проверяются маршруты и закрепления, избранное, даты, погодные рекомендации, URL карт и билетов, стабильный порядок и удаление поездок. Старый расчётный модуль бюджета сохранён для возможного будущего учёта расходов, но не участвует в текущих пользовательских настройках.

RAG benchmark пока **не запускается**: корпуса, поиска и runner нет. Статус сохранён в `benchmark/results/`. Сценарии ручной проверки находятся в `spec/product/scenarios.md`.

## Ограничения и следующий этап

Генерация LLM и BM25, реальные музейные расписания, живые цены, бронирование, оплата, аккаунты, мобильная версия и расчёт оптимальных переходов ещё не реализованы. Бюджет в подборе города — пожелание, а не подтверждённая стоимость поездки.

Следующий этап: подготовить корпус европейских путеводителей с источниками, подключить BM25 и LLM, согласовать серверный контракт и прогнать benchmark по поиску и ответам.
