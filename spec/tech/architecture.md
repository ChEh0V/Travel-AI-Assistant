# Архитектура

## Схема

```
Интерфейс (app/)  ──POST /api/chat {messages}──▶  Бэкенд
                  ◀──── {reply, sources} ──────     ├─ BM25-поиск по корпусу путеводителей
                                                    └─ LLM: ответ по найденным фрагментам
```

1. Интерфейс отправляет историю диалога.
2. Бэкенд строит поисковый запрос из последнего вопроса (и города из контекста).
3. BM25 возвращает top-k фрагментов корпуса.
4. LLM получает вопрос + фрагменты и формирует ответ со ссылками на источники.

Подробно про поиск — `rag.md`.

## Текущая версия (КТ1)

```
app/index.html  — разметка и стили чата
app/app.js      — логика чата (отправка, рендер, индикатор)
app/mock.js     — заглушка: getReply(messages) отвечает по ключевым словам
```

Сервер не нужен. Для перехода на бэкенд заменяется только `getReply()` в `mock.js` на `fetch("/api/chat")`.

## Контракт API

`POST /api/chat`

```json
{ "messages": [{ "role": "user", "content": "Что посмотреть в Риме?" }] }
```

Ответ:

```json
{ "reply": "...", "sources": [{ "doc": "rome.md", "chunk": 3 }] }
```
