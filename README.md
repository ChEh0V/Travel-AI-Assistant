# Попутчик

**Контекстный ассистент для путешествий по Европе.** Обсудите поездку в чате, сохраните понравившиеся места и соберите маршрут по дням.

## О проекте

Учебный проект НИРС, группа ИУ5-51Б. Пользователь — самостоятельный путешественник, который планирует короткую поездку и собирает информацию из разных путеводителей. Цель «Попутчика» — сохранить пожелания в одном диалоге, помочь выбрать направление и превратить выбранные места в редактируемый план.

Справочные вопросы о европейских направлениях используют BM25 и документы с источниками. Для генерации можно подключить модель с совместимым Chat Completions API. Без модели сервер составляет ответ из полей найденных документов.

Навигация: [документация](docs/README.md) · [требования](spec/product/product.md) · [сценарии](spec/product/scenarios.md) · [план работ](spec/plan.md) · [проверки](spec/verification.md).

## Статус проекта

В стартовой SQLite 102 документа: 51 страновой путеводитель, 21 городской путеводитель и 30 карточек парижских музеев и событий. Географический охват включает европейские микрогосударства, Косово, Россию, Турцию, Казахстан и три страны Южного Кавказа. По каждой из 72 географических карточек доступны обзор и места для посещения, по части карточек также местная кухня. Источники обновлений — Викигид, Википедия, Muséofile, Wikidata и Que Faire à Paris. Маршруты для шести городов по-прежнему обрабатываются локальным планировщиком.

## Быстрый запуск

Для запуска чата с генерацией через Qwen выполните [настройку Ollama](#первый-запуск-с-qwen-на-windows). Веса модели скачиваются один раз отдельно от репозитория.

Чтобы запустить чат в режиме ответа по документам, достаточно Python 3.10 или новее. Из корня репозитория:

```bash
python rag/server.py serve
```

Для первого запуска получите репозиторий: `git clone https://github.com/ChEh0V/Travel-AI-Assistant.git`, затем `cd Travel-AI-Assistant`. Остановить сервер можно через Ctrl+C. API-ключи, `.env`, Docker и установка базы данных для КТ1 не нужны.

Откройте **http://localhost:8000/#chat**. Устанавливать npm-пакеты не требуется.

Для прогноза погоды нужен доступ к Open-Meteo. Шрифт Manrope загружается из Google Fonts; при отсутствии сети используется системный шрифт. Маршруты, избранное и сборы хранятся локально в браузере, без аккаунта и серверной БД.

## Основной сценарий

1. Напишите «Составь маршрут по Парижу на 2 дня» или нажмите пример на стартовом экране.
2. Уточните: «Сделай спокойнее», «Больше бесплатного», «Замени музеи на прогулки».
3. Нажмите **«Хочу сюда»** у понравившихся мест. Откройте список, чтобы посмотреть или убрать сохранённые места. Для нового плана напишите «Собери маршрут из избранного»: в него войдут места текущего города.
4. Задайте общие даты поездки кнопкой в шапке или сообщением, например «25.10–27.10». Маршрут, погода и сборы используют один период.
5. В **«Моих поездках»** откройте чат, маршрут или сборы нужной поездки. Порядок карточек не меняется при переключении.

## Возможности макета

- Чат, быстрые уточнения, подбор города по свободному описанию и подборка «Инстаграмные места».
- Качественные предпочтения жилья, еды, транспорта, впечатлений и компании. Вайба, денежных ползунков и обязательной большой формы нет.
- Маршрут на 1–3 дня: перестановка карточек одного дня перетаскиванием или стрелками, закрепление и экспорт TXT. Заменить остановку можно через поиск и «Хочу сюда» в маршруте или попросив об этом в чате по названию места.
- «Хочу сюда» хранит список мест для замены остановок или сборки маршрута из чата.
- Кнопка «Отправить в чат» передаёт текущие настройки поездки Qwen и показывает их в переписке.
- Ссылки на Google Maps, отзывы и последовательность остановок дня. Официальные билетные страницы для мест в шести городах, у музеев Ватикана также есть ссылка на календарь доступности. Дата в карточке взята из маршрута, доступность проверяется на сайте площадки.
- Чат, маршрут и TXT показывают время каждой остановки. День начинается в 10:00 по местному времени, начало можно изменить отдельно для каждого дня. Между остановками заложено 30 минут, посещение занимает ориентировочно час, музей — два. Билетная ссылка показывает планируемое время для проверки на сайте.
- Смешанный план сочетает прогулки и билетные места. Команда «Добавь места с билетами» заменяет часть незакреплённых прогулок в текущем маршруте. У некоторых прогулок есть необязательная экскурсия с отдельным бронированием.
- Для круиза по Сене приложение запрашивает публичный календарь Vedettes du Pont Neuf на дату остановки и показывает ближайший доступный рейс для одного человека или двоих в режиме «Вдвоём». При отсутствии свободных рейсов прогулка по набережной остаётся в плане. Доступность остальных площадок проверяется по билетным ссылкам. Из шапки чата маршрут открывается одной кнопкой.
- Сборы: базовый чек-лист, собственные пункты, отметки и советы по одежде. Прогноз Open-Meteo доступен на ближайшие даты в пределах 16 дней. В маршруте показан прогноз выбранного дня, а чат берёт данные из того же прогноза поездки.
- До 12 локальных поездок, поиск, сохранение истории, дат, избранного и сборов.
- **Удалить маршрут:** очищается только план; чат, даты, сборы и избранное сохраняются.
- **Удалить поездку:** удаляется вся выбранная поездка после подтверждения, остальные остаются на месте.

Единственная цветовая тема — синяя «Атлантика»; символ проекта — компас. Основная навигация содержит «Ассистент» и «Мои поездки»; маршрут и сборы открываются в контексте конкретной поездки.

### Как устроен и проверяется поиск

В полном снимке 102 документа. В 34 поисковых вопросах размечено по три релевантных документа: каждая карточка входит в эталон один раз. Вопросы охватывают обзоры стран и городов, достопримечательности, кухню, музеи и события. Пять дополнительных ловушек оценивают отказ отдельно. [Европейские вопросы](benchmark/europe.json) · [Парижские вопросы и ловушки](benchmark/paris.json) · [Выдача и метрики](benchmark/results/europe-snapshot.json).

Для воспроизведения исходного учебного объёма выполните `python rag/benchmark.py --course`. Учебный поднабор включает 24 страны и 6 городов. В нём два вопроса-продолжения, пять вопросов без подтверждённого ответа в корпусе и по три эталонных документа на каждый обычный вопрос. На этом поднаборе самостоятельный BM25 получил Recall@5 = 0,800 и MRR = 0,813. [Вопросы для сдачи](benchmark/course.json) · [Ответы и метрики учебной проверки](benchmark/results/europe-course.json).

**Предобработка.** Документы и поисковые запросы проходят одну функцию токенизации. Последовательность букв или цифр образует токен, пробелы и знаки пунктуации служат разделителями. Это сохраняет числа из адресов и дат и позволяет искать части составных названий. Приведение регистра, замена «ё» на «е» и удаление комбинируемых знаков после Unicode-нормализации позволяют сопоставлять разные написания, например *Musée* и *musee*. Упрощение может объединить разные слова. Стоп-слова сохраняются: распространённые термы получают меньший вес IDF. Общая лемматизация отключена, поскольку корпус сочетает русские запросы с французскими именами и адресами. Для ряда названий предусмотрены варианты написания и склонения; произвольная русская словоформа может пропустить совпадение.

**Самостоятельный BM25.** Обратный индекс хранит для каждого терма ID документов и частоту в каждом из них. Ранжирование учитывает редкость терма и длину документа; параметры k1 = 1,2 и b = 0,75. Команда `python rag/benchmark.py` сначала проверяет сам индекс по всем 102 документам на последней реплике каждого запроса. Recall@5 измеряет долю найденных эталонов в первой пятёрке. Для MRR берётся обратная позиция первого релевантного документа во всей выдаче; при отсутствии совпадений вклад равен нулю.

**Результат на фиксированном снимке.** У самостоятельного индекса Recall@5 = 0,892, MRR = 0,904. У прикладного поиска с фильтрами и восстановлением названия музея из диалога Recall@5 и MRR@5 равны 1,0. В частности, вопрос «Что там проходит?» сам по себе не указывает площадку. Без переписывания прикладной поиск получил по 0,941 по обеим метрикам; расширение запроса после переписывания результата на этой выборке не изменило. Это учебная разметка; оценка на новых вопросах потребует независимого набора. В [прогоне с локальной Qwen 3B](benchmark/results/europe-qwen-3b.json) проверку фактов и цитат прошли 3 формулировки модели из 34. В остальных 31 случае сервер вернул исходные выдержки, а на 5 ловушках ответил отказом до генерации.

## Обновление и модель

Один раз обновить SQLite: `python rag/server.py refresh`. Для автоматического обновления при запуске и затем каждые 24 часа: `python rag/server.py serve --refresh-hours 24`. Снимок в Git и benchmark сохраняют исходные данные.

### Первый запуск с Qwen на Windows

Установите Python 3.10+ и [Ollama](https://ollama.com/download/windows), затем запустите приложение Ollama. В PowerShell из корня клона выполните:

```powershell
ollama pull qwen2.5:3b
$env:RAG_MODEL = "qwen2.5:3b"
python rag/server.py serve
```

Первая команда один раз скачивает [веса модели (около 1,9 ГБ)](https://ollama.com/library/qwen2.5:3b). Для повторного запуска в новом терминале достаточно последних двух команд. Откройте http://127.0.0.1:8000/#chat. Снимок корпуса входит в Git, SQLite создаётся автоматически. Для проверки самой генерации используйте `python rag/benchmark.py --llm` в терминале с заданным RAG_MODEL. Обычный запуск без этой переменной показывает ответы напрямую из документов.

Примеры вопросов: «Что посмотреть в Германии?», «Что посмотреть в Берлине?», «Расскажи про Италию» → «Какая там кухня?», «Адрес музея Орсе?» → «Какие там события?». Категория стоимости события относится к опубликованной афише. Наличие билетов, часы открытия и точная стоимость требуют других источников.

Чтобы проверить свободный диалог с Qwen, соберите маршрут и напишите «Хочу что-то весёлое». Модель получает текущую поездку и может предложить идеи. Если локальный прокси возвращает ошибку при обращении к Ollama, добавьте `127.0.0.1` и `localhost` в `NO_PROXY` перед запуском сервера.

Для контрольной точки прогоните именно учебный набор при запущенной Ollama:

```powershell
$env:RAG_MODEL = "qwen2.5:3b"
python rag/benchmark.py --course --llm --out benchmark/results/course-qwen-local.json
```

В отчёте сохраняются выдача, ответ, источники и режим каждого из 15 вопросов. `llm` означает, что формулировка Qwen прошла проверку, `extractive-fallback` — что приложение вернуло исходный текст из найденных документов. Для ловушек без подтверждённого ответа модель не вызывается. Итоговые поля `recall`, `mrr`, `accuracy` и `correct_rejection_rate` показывают качество поиска и ответов. Зафиксированный [учебный прогон](benchmark/results/europe-course.json) сделан в режиме ответа по документам.

В учебном прогоне без переписывания запроса два вопроса-продолжения (C02 про кухню Балтии и C04 про достопримечательности Германии, Австрии и Швейцарии) не получили правильный ответ: слово «там» не указывает страны без предыдущей реплики. С восстановлением названий стран из диалога оба ответа прошли проверку. Все пять ловушек получили корректный отказ в обоих режимах.

В [локальном учебном прогоне с Qwen 2.5 3B](benchmark/results/course-qwen-local.json) все 10 обычных вопросов получили правильные ответы из документов в режиме `extractive-fallback`, все 5 ловушек получили отказ. Эти метрики относятся к ответам системы в целом. Генерация отдельно подтверждена через API чата вопросом «Где расположены музеи Карнавале, Пикассо и Оранжери?» (режим `llm`, три источника).
